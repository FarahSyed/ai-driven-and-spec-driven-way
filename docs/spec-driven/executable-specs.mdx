# 3.2 What Executable Specifications Actually Are  
From “comments that lie” to living mathematical contracts

An executable specification is a machine-checked formal statement of what the system must do — independent of how it does it.

It is not a test.  
It is not documentation.  
It is the source of truth that both humans and AI agents consult before any implementation is written.

### The Four Layers (2025 taxonomy)

| Layer               | Purpose                                                   | Typical Tool (2025)                  | Example Syntax (Spec-Kit Plus)                                 |
|---------------------|-----------------------------------------------------------|--------------------------------------|----------------------------------------------------------------|
| 1. Property-based   | Invariants over infinite input spaces                     | Spec-Kit Plus, Hedgehog, ZIO-Test    | `forall((a, b) => add(add(a, b), c) === add(a, add(b, c)))`   |
| 2. Model-based      | Simulate a simpler “golden” model and compare             | Spec-Kit Plus StateMachine, Quint    | `model.run(commands).equals(implementation)`                  |
| 3. Design-by-Contract | Pre/post-conditions + invariants on every public function | Spec-Kit Plus Contracts, Eiffel-style| `@requires(balance >= amount) @ensures(balance' == balance - amount)` |
| 4. Temporal / Protocol | Message ordering, session types, saga guarantees          | Spec-Kit Plus Temporal, TLA+ 2025    | `[] (sent(OrderPlaced) => <> received(OrderConfirmed))`       |

### The Killer Feature: Counterexample Shrinkage

```ts
// Spec-Kit Plus (TypeScript)
spec("transfer preserves total supply", ({gen}) => {
  const {accounts, transfer} = setup()
  const initialSupply = totalSupply(accounts)

  forAll(
    gen.accountId, gen.accountId, gen.positiveInt
  )((from, to, amount) => {
    transfer(from, to, amount)
    expect(totalSupply(accounts)).toEqual(initialSupply)
  })
})
```

Run this once → 10 000+ random transfers (including negative amounts, same-account, overflow attempts).
If anything ever changes total supply, Spec-Kit instantly shrinks to the minimal failing case:

```text
Counterexample found after 1 237 tests:
from: "Alice", to: "Alice", amount: 9223372036854775808
→ overflow bug in unchecked arithmetic
```

You now know the exact edge case — without ever writing it by hand.

### Why This Beats Every Other Approach

| Technique                    | Input space covered     | Time to write       | Time to find bug      | False negatives      |
|------------------------------|-------------------------|---------------------|-----------------------|----------------------|
| Hand-written unit tests      | &lt;0.0001 %               | High                | Days–never            | Extremely high       |
| Classic property testing     | 0.1–1 %                 | Medium              | Minutes               | Medium               |
| Executable specifications    | &gt;99.999 %               | Low                 | Milliseconds          | Near zero            |
