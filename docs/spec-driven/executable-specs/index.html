3.2 What Executable Specifications Actually Are

From “comments that lie” to living mathematical contracts

An executable specification is a machine-checked formal statement of what the system must do — independent of how it does it.

It is not a test.
It is not documentation.
It is the source of truth that both humans and AI agents consult before any implementation is written.

The Four Layers (2025 taxonomy)​

LayerPurposeTypical Tool (2025)Example Syntax (Spec-Kit Plus)
1. Property-basedInvariants over infinite input spacesSpec-Kit Plus, Hedgehog, ZIO-Testforall((a, b) => add(add(a, b), c) === add(a, add(b, c)))

The Killer Feature: Counterexample Shrinkage​

// Spec-Kit Plus (TypeScript)
spec("transfer preserves total supply", ({gen}) => {
  const {accounts, transfer} = setup()
  const initialSupply = totalSupply(accounts)

  forAll(
    gen.accountId, gen.accountId, gen.positiveInt
  )((from, to, amount) => {
    transfer(from, to, amount)
    expect(totalSupply(accounts)).toEqual(initialSupply)
  })
})

Run this once → 10 000+ random transfers (including negative amounts, same-account, overflow attempts). If anything ever changes total supply, Spec-Kit instantly shrinks to the minimal failing case:

Counterexample found after 1 237 tests:
from: "Alice", to: "Alice", amount: 9223372036854775808
→ overflow bug in unchecked arithmetic

You now know the exact edge case — without ever writing it by hand.
