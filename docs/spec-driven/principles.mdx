# 3.3 Core Principles  
The three ideas that separate 2025 elite teams from everyone else

### Principle 1: Properties Over Examples

An **example** tells you the system works for one path.  
A **property** tells you the system works for 10¹⁵ paths — or instantly shows you the one where it doesn’t.

```ts
// Example-based (2024 mindset)
test("transfers work", () => {
  transfer(alice, bob, 100)
  expect(balance(alice)).toBe(900)
  expect(balance(bob)).toBe(1100)
})

// Property-based (2025 mindset)
property("transfer never creates or destroys money", () => {
  const before = totalSupply()
  transfer(any.account, any.account, any.amount)
  expect(totalSupply()).toEqual(before)
})
```

The second version automatically tries:

- Negative amounts
- Same sender/receiver
- Max-int overflows
- Concurrent transfers
- Zero amounts
… and 9 999 995 other cases you never thought of.

If it ever fails, you get the smallest possible counterexample in &lt;300 ms.


### Principle 2: Design by Contract (DbC)

Every public function now carries legally binding pre- and post-conditions.

```ts
// Spec-Kit Plus + TypeScript (2025 style)
@contract
function withdraw(accountId: AccountId, amount: PositiveBigInt): void {
  requires(balanceOf(accountId) >= amount, "insufficient funds")
  requires(!isFrozen(accountId), "account frozen")
  ensures(balanceOf(accountId) === old(balanceOf(accountId)) - amount)
  ensures(totalSupply() === old(totalSupply()))
}
```

The runtime (or static analyzer) enforces these at CI time.
The AI agent reads them before generating any implementation.
Violate one → PR blocked instantly.
Real result from a major exchange in 2025:
→ 100 % of double-spend attempts by AI-generated code were rejected before the PR was even opened.

### Principle 3: Refinement (The Holy Grail)
You write two models:

A simple, obviously correct model (usually &lt;100 lines)
The real implementation

Then you prove every behavior of the real system is allowed by the simple model.

```ts
// Simple, correct-by-inspection model
class IdealBank {
  balances = new Map<string, bigint>()
  transfer(from: string, to: string, amount: bigint) {
    this.balances.set(from, this.balances.get(from)! - amount)
    this.balances.set(to, this.balances.get(to)! + amount)
  }
}

// Real optimized sharded version with fees, batches, etc.
class ProductionBank { ... }

// Refinement check (runs 10 M simulated days in <3 seconds)
spec("ProductionBank refines IdealBank", () => {
  modelBased(IdealBank)
    .withImplementation(ProductionBank)
    .check()
})
```

If the production version ever diverges (even by one satoshi), the suite fails with a step-by-step trace.
This is how teams ship zero-incident financial systems while moving 10× faster.
